# Публикация на GitHub Pages

Витрина — статический HTML, поэтому Pages ей подходит целиком. Сборщик тоже
можно держать в GitHub Actions: раннеры имеют доступ в интернет, отдельный
сервер для MVP не нужен.

---

## Что делаете вы, а что уже готово

Готово в репозитории: `.github/workflows/pages.yml` (сборка данных + деплой),
`.github/workflows/tests.yml` (тесты на каждый push), `.gitignore`.

Дальше нужны ваши учётные данные, поэтому эти шаги — за вами. Пароли и токены
я не ввожу и не храню.

---

## 1. Создать репозиторий

На github.com → **New repository** → имя, например `subsidy-flights`.
Публичный или приватный — Pages работает и с приватным на платных тарифах,
на бесплатном нужен публичный.

**Важно:** репозиторий будет публичным, а значит виден будет и код, и
`PartnerID` из `config.py` по умолчанию (`KirillTest`). Тестовый — не страшно.
Боевой PartnerID в код не вписывайте: он идёт только в Secrets.

## 2. Загрузить файлы

```bash
cd путь/к/проекту
git init
git add .
git commit -m "Мониторинг субсидированных билетов: сборщик и витрина"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/subsidy-flights.git
git push -u origin main
```

Проверьте перед пушем, что `.env` не попал в индекс:

```bash
git status --short | grep -F .env && echo "СТОП: .env в индексе" || echo "ок"
```

## 3. Включить Pages

Settings → **Pages** → Build and deployment → Source: **GitHub Actions**.
Именно Actions, не «Deploy from a branch» — иначе воркфлоу не сможет
опубликовать артефакт.

## 4. Прописать секреты (когда будет боевой доступ)

Settings → Secrets and variables → Actions → **New repository secret**:

| Имя | Значение |
|---|---|
| `BILETDV_PARTNER_ID` | боевой PartnerID от партнёра |
| `BILETDV_API_URL` | точный URL метода поиска |
| `BILETDV_LOGIN` / `BILETDV_PASSWORD` | если партнёр выдаст |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | для алертов, необязательно |

Пока `BILETDV_PARTNER_ID` пуст или равен `KirillTest`, воркфлоу собирает
**демо на фикстуре**: страница выходит с жёлтым баннером «демо-режим»,
кнопки покупки отключены, в `<head>` ставится `noindex` — поисковики её
не проиндексируют. Это сделано специально: публичная страница с вымышленными
рейсами и ценами под именем ИП — репутационный риск.

## 5. Запустить

Actions → «Публикация витрины на GitHub Pages» → **Run workflow**.
Через минуту-две адрес появится в логе шага deploy и в Settings → Pages:

```
https://ВАШ_ЛОГИН.github.io/subsidy-flights/
```

---

## Как обновляется

Расписание в `pages.yml` — каждые 15 минут. История наличия мест нужна
алертам «места появились / кончились», а раннер одноразовый, поэтому база
переносится между запусками через `actions/cache`.

---

## Ограничения этой схемы — прочитайте до того, как строить на ней бизнес

* **Расписание Actions не гарантированное.** GitHub прямо пишет, что
  `schedule` может задерживаться при нагрузке на раннеры, а на непопулярных
  минутах — пропускаться. Реальный интервал плавает от 15 минут до часа.
  Для «посмотреть, работает ли идея» годится; обещать пользователям
  проверку каждые 15 минут на этом нельзя.
* **Кэш — не база данных.** `actions/cache` вытесняется при переполнении
  (лимит 10 ГБ на репозиторий) и удаляется после 7 дней без обращений.
  Потеря кэша означает потерю истории: алерты один раз отработают как
  «вижу рейсы впервые». Данные наблюдений при этом не критичны, но графики
  «как таяли места» оборвутся.
* **Минуты Actions не бесконечны.** На приватном репозитории бесплатный
  лимит 2000 минут в месяц. Запуск раз в 15 минут — это ~2900 запусков,
  и даже по минуте на запуск лимит вы пробьёте. На публичном репозитории
  Actions бесплатны, поэтому для MVP репозиторий лучше публичный.
* **Подписка на уведомления не работает** — форма на витрине ничего не
  отправляет. Для приёма адресов нужен бэкенд, а Pages отдаёт только
  статику. Варианты: внешняя форма (Google Forms, Tally), Formspree,
  либо перенос на VPS.
* **Свой домен.** Settings → Pages → Custom domain, плюс CNAME у регистратора
  на `ВАШ_ЛОГИН.github.io`. Сертификат Pages выпустит сам.

**Когда переезжать на VPS:** как только (а) нужен честный интервал опроса,
(б) появятся подписки на уведомления, (в) партнёр разрешит white-label на
своём домене. Инструкция по VPS — в `README.md`.
