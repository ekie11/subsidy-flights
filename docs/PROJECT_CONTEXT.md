# Контекст проекта: мониторинг субсидированных авиабилетов

Обновлено: 20 августа 2026.

## Суть

Сервис показывает **живое наличие свободных мест** по субсидированным
авиабилетам (дальневосточная субсидия по прописке в ДФО, молодёжная,
пенсионеры, многодетные, инвалиды и др.). Обычные поисковики показывают тариф,
которого уже нет; ценность — в остатке квоты, а не в цене (цена фиксирована
государством).

Модель: показываем наличие → переход на покупку к партнёру по реферальной
ссылке → комиссия. Билеты сами не продаём, деньги клиентов через себя не
проводим.

Владелец: Кирилл Харханов, harhanovk@gmail.com. GitHub: `ekie11`.
Юрформа: нужен **ИП или ООО** (самозанятость партнёр не принимает).

## Партнёр

**БилетДВ** (biletdv.ru), АО «Дальневосточное авиационное агентство Спектр Авиа
Сервис», Хабаровск. Контакт: Сергей Ивлев, директор по ИТ и e-commerce.

* Комиссия 1,5%, выплата раз в месяц, за вычетом возвратов.
* Тестовый доступ: `PartnerID=KirillTest`, маршруты KHV-MOW и KHV-LED,
  даты 01.10–30.10.2026.
* Поля ответа: `AvailQty` (наличие мест), `FareCode="PZZSOC"` (субсидия у
  Аэрофлота), `MRID` (признак субсидии), `BookURL` (со вшитым PartnerID).

### Договор
Два типа на uniagent.ru:
* **«Комиссионный»** — доступа к API нет. Не подходит.
* **«Веб-модуль (white label)»** — даёт API. Выбирать его.
  * White label в IFRAME — сразу;
  * на своём домене без IFRAME (`book.<домен>.ru`) — после 100 продаж/мес
    без учёта возвратов.

### Категории льгот (полный список)
Категория — отдельный числовой параметр на тип пассажира (как взрослые/дети):
`MLA=1` = один пассажир категории «молодёжь».

| Код | Категория |
|---|---|
| `MLA` | Молодёжь, 2–23 года |
| `AAA` | Любой взрослый пассажир |
| `RBG` | Ребёнок 2–12 лет |
| `RMG` | Ребёнок до 2 лет без места |
| `RVG` | Ребёнок до 2 лет с местом |
| `CPA` | Пенсионер (м 60+, ж 55+) |
| `DIS` | Инвалид |
| `ADD` | Сопровождающий инвалида |
| `FBA` | Родитель многодетной семьи |

Эндпоинт для запроса по категориям:
`http://fares.biletdv.ru/SasSirenaFares.asmx?op=getFaresByFOP_Ex3`
(ответ по структуре как у `getFaresByFOP`).

Открытый вопрос: можно ли в одном запросе передать несколько категорий
(`MLA=1&AAA=1`) или нужен отдельный вызов на каждую.

### Коды тарифов
Произвольные, у каждой авиакомпании свои (Аэрофлот: `PZZSOC` — молодёжь,
`PSOCDO` — ДФО; Уральские: `UBDOWZZ`, `RBDOWD`). Определять категорию по
шаблону кода нельзя — только по параметру запроса.

### Прочее
* Календарного метода нет — один запрос на одну дату.
* **Лимит: не более 1000 запросов на одну продажу** (look-to-book).
* `AvailQty` кэшируется, TTL в `Cache_Best_Before` на уровне предложения.
* Перечень маршрутов — xlsx-реестр Росавиации:
  https://favt.gov.ru/public/materials//9/c/0/8/7/9c087d57e74340c16b8d34d0e62a4114.xlsx
  (дата обновления плавающая — нужен периодический опрос).
* Cookie-атрибуция 30 суток, почти не используется.
* Окно возвратов — 1 год.
* **Публикация наличия мест разрешена только при показе времени последнего
  обновления рядом с календарём.**

## Что НЕ работает
* Подписка на уведомления — форма ничего не отправляет (нужен бэкенд).
* Категория льготы не фильтрует выдачу.
* Не генерируется `PersonID`.
* Фикстура выдуманная — на боевом доступе сохранить реальный XML в `fixtures/`.
* Время обновления на витрине не показано рядом с календарём (требование партнёра).
* Расписание GitHub Actions негарантированное, кэш с базой вытесняется.
* Квадратик «вне мониторинга» в легенде календаря сливается с фоном.

## Проблема масштаба
~600 маршрутов × 120 дат = 72 000 комбинаций; раз в 15 минут = 6,9 млн
запросов/сутки. Look-to-book выходит ~520 000:1 при лимите 1000:1.

**Решение (обязательное):** опрашивать только то, на что есть подписка;
без подписок — раз в сутки для витрины. Подписка — ядро продукта. Нужен
бэкенд и VPS вместо GitHub Pages. Плюс: дельта-хранение, загрузчик реестра
Росавиации, учёт `Cache_Best_Before`, `PersonID` в каждой ссылке.

## Юридическое и налоговое
ИП на УСН «Доходы» 6%. Взносы 2026: 57 390 ₽/год + 1% свыше 300 тыс.
Порог НДС для УСН — 20 млн ₽ (2026). Деньги клиентов не должны идти через
ваш счёт. Открывать ИП, когда партнёр готов подписывать.
