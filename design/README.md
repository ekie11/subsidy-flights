# Дизайн витрины: макет и реальная сборка

`index.html` в этой папке — исходный макет: самодостаточный демо-файл на
вымышленных рейсах, открывается в браузере без сборки (для правки вёрстки
и анимаций). `checkout.html` — форма данных пассажиров, тоже самодостаточная:
рейс ей передают через параметры адреса, своей базы данных у неё нет.
Оба используют общий `assets/tokens.css` — палитру, тёмную тему и базовые
утилити-классы. Раньше каждая страница держала свою копию токенов и они
расходились (`--red-bg` и `--shadow-card` были только в одном из файлов) —
теперь источник один, страницы просто подключают его через `<link>`.
Компонентные стили (шапка, поиск, форма, календарь) и вся логика остаются
в каждом файле локально — они у страниц разные и делить их не стоит.

Кнопка «Купить у партнёра» на витрине открывает форму с выбранным рейсом:
маршрут, дата, время, число пассажиров и категория льготы передаются в адресе. Данные о рейсах, местах и отзыв в нём
вымышленные, покупка и подписка не подключены (об этом говорит плашка вверху).

На **боевую** витрину `/design/` этот `index.html` не публикуется напрямую.
`design_app.py` (в корне репозитория) строит из него другую страницу — та же
вёрстка, стили и анимации, но вместо CITIES/SEATS/DAY12 из макета вшиты
реальные данные сборщика (как `webapp.py` для основной витрины): рейсы,
маршруты из `config.ROUTES`, категории льгот из `cities.py`, демо-баннер и
`noindex` включаются автоматически при отсутствии боевого PartnerID.

    python design_app.py                      # data/design/index.html
    python design_app.py --out /var/www/html/design/index.html

`checkout.html` в сборке не участвует и копируется как есть — он не знает
о базе, а получает рейс через адрес (`date`, `carrier`, `num`, `seats`, …).
Полей, которых партнёрский API не отдаёт (модель самолёта, длительность
перелёта, пересадки), в реальной сборке нет — их не выдумываем.

Что уже подключено к реальным данным:

- поиск ограничен маршрутами из `config.ROUTES` (не любой из 11 городов
  макета — только то, что реально отслеживается);
- рейсы, места и цены — из `data/subsidy.sqlite3`; календарь и табло
  на боковой панели считаются по тем же данным;
- категории льгот и их требования — из `cities.CATEGORIES`, полное название
  перевозчика — из справочника `cities.AIRLINES` по коду авиакомпании;
- честные пустые состояния: «эту дату не отслеживаем» (вне окна
  `config.DATE_FROM..DATE_TO`) и «мест на эту дату нет» (в окне, но пусто).

Что осталось макетом (сознательно, не бэкендом):
подписка на Telegram/почту, отзыв, сравнение с агрегаторами, форма
пассажиров в `checkout.html` — данные из неё никуда не уходят, оформление
остаётся в кассе партнёра. Если это изменится, сайт станет оператором
персональных данных (152-ФЗ): уведомление Роскомнадзора, политика обработки,
хранение в России.

Шрифты (Onest, JetBrains Mono), иконки Phosphor и Motion лежат в
`assets/vendor/`, внешних CDN страницы не используют. Шрифт иконок урезан до
тех, что есть в разметке (`assets/vendor/phosphor.css`). Новая иконка
Phosphor: добавить её класс и код в `phosphor.css` и пересобрать шрифт из
пакета `@phosphor-icons/web@2.1.1`:

    pyftsubset node_modules/@phosphor-icons/web/src/regular/Phosphor.woff2 \
      --unicodes=U+e5de,U+e0a0,... --flavor=woff2 \
      --output-file=assets/vendor/fonts/Phosphor-subset.woff2
